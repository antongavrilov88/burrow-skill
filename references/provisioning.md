# Где брать машины и как доставить установщик

Это техническая справка для тебя. То, что нужно сказать человеку и какие
кнопки он жмёт, — в `human-steps.md`; здесь только механика.


## Выходная машина (за границей)

Минимум: Ubuntu 24.04, 1 vCPU, 1 ГБ памяти, честный публичный IPv4, разумная
квота исходящего трафика. Этого хватает на гигабит — узкое место всегда трафик,
а не процессор.

**DigitalOcean** — то, под что написан `provision-do.py`: `s-1vcpu-1gb`, $6/мес,
1 ТБ. Регион ближе к пользователям: `fra1` (Франкфурт) для Европы и запада РФ,
`ams3` — примерно то же, `sgp1` — для Азии.

Что важно при создании через API:

- **`ssh_keys` передавать обязательно.** Без него DigitalOcean включает режим
  «смените пароль при первом входе» и не пускает даже по ключу. `provision-do.py`
  на это ругается заранее.
- Установщик передаётся как `user_data` — cloud-init выполнит его при первой
  загрузке. Предел 64 КБ, установщик занимает около 46 КБ. Если однажды не
  влезет, ставь по SSH.
- Тег `vpn-exit` — по нему потом ищется и удаляется машина. Без тега `destroy`
  откажется работать.

**Hetzner, Vultr, любой другой** — годятся так же, просто создавай машину
руками и ставь установщик по SSH.

Другие полезные вызовы:

```bash
export DO_TOKEN=...
python3 scripts/provision-do.py check                      # токен живой? карта привязана? сколько машин?
python3 scripts/provision-do.py new-key --out ~/.ssh/vpn-kit  # создать ключ и залить в аккаунт
python3 scripts/provision-do.py keys                       # id SSH-ключей на аккаунте
python3 scripts/provision-do.py list                       # все машины (проверить счёт)
python3 scripts/provision-do.py list --tag vpn-exit        # только наши
python3 scripts/provision-do.py wait-ssh --ip <IP>         # дождаться загрузки
python3 scripts/provision-do.py destroy --id <id> --tag vpn-exit
```

Если из сессии не достучаться до `api.digitalocean.com` (сеть закрыта) —
все те же шаги делаются в веб-интерфейсе DigitalOcean: Create → Droplet →
Ubuntu 24.04 → Basic → Regular $6 → регион → SSH-ключ → Advanced options →
Add Initial Scripts → вставить содержимое `out/setup-exit.sh` → Tags: `vpn-exit`.

## Релей (внутри страны)

API у российских провайдеров нет общего, поэтому машину человек берёт сам.
Требования те же плюс два:

- **дешёвый или бесплатный входящий трафик** — через релей пройдёт весь трафик
  пользователей дважды;
- **не тот же провайдер, что у выходной машины**, очевидно.

Подходят Yandex Cloud, Selectel, Timeweb, Beget, aeza и любой VPS в РФ
за 300–600 ₽/мес. У Yandex Cloud первые 100 ГБ исходящего бесплатно,
дальше по прайсу — при семейном сценарии счёт заметный, стоит посчитать заранее.

Что нужно от человека: IP, пользователь с sudo без пароля (или root) и SSH-ключ.

## Как доставить установщик на готовый сервер

По порядку предпочтения.

**1. Через SSH из сессии**, если есть подходящий инструмент (`mcp-ssh`,
`device_bash` с доступом наружу):

```bash
scp out/setup-relay.sh root@<IP>:/root/
ssh root@<IP> 'bash /root/setup-relay.sh'
```

Установка идёт 5–10 минут. Если инструмент рвёт команды по таймауту (у многих
предел 60 секунд) — запускай в фоне и следи за логом:

```bash
ssh root@<IP> 'setsid nohup bash /root/setup-relay.sh > /var/log/vpn-kit-install.log 2>&1 & disown'
ssh root@<IP> 'tail -20 /var/log/vpn-kit-install.log'
```

**2. Через cloud-init**, если машина ещё не создана: содержимое `setup-*.sh`
целиком в поле пользовательских данных при создании.

**3. Отдать файл человеку.** Пошли `setup-relay.sh` через SendUserFile и веди
его по `human-steps.md` §7 — там расписано, как открыть терминал на каждой
системе, что пароль не отображается при вводе и что ответить на вопрос про
`yes`. Сами команды:

```bash
scp ~/Downloads/setup-relay.sh root@<IP>:/root/
ssh root@<IP> 'bash /root/setup-relay.sh'
```

Попроси прислать последние 20 строк вывода — по ним видно, сошлось или нет.

## DNS

Нужны три A-записи на IP выходной машины: `@`, `www`, `push`.

Если домен в DNS DigitalOcean — ставятся сами:

```bash
python3 scripts/provision-do.py dns --domain <домен> --ip <IP> --names @ www push
```

Если нет — человек ставит их у своего регистратора. TTL поставить 300 секунд:
при замене машины после бана это экономит часы ожидания.

Проверить, что разошлось — сам, а не вопросом человеку:

```bash
python3 scripts/provision-do.py ns-check   --domain <домен>              # куда делегирован
python3 scripts/provision-do.py dns-check  --domain <домен> --ip <IP>    # разошлись ли записи
```

`ns-check` возвращает 0, если домен в DigitalOcean (можно ставить записи
самому), 2 — если у регистратора (человек ставит руками, `human-steps.md` §5),
3 — если DNS вообще не спросить из этой сессии; тогда попроси открыть
dnschecker.org.

Сертификаты выпускаются установщиком автоматически, но он ждёт DNS — до шести
попыток с минутными паузами. Если A-записи поставили позже, просто запусти
установщик ещё раз, он идемпотентный.

## Повторный запуск

Все установщики можно запускать сколько угодно раз. Что уже настроено — не
трогается: существующий `wg-clients.conf` не перезаписывается, выданные
сертификаты не перевыпускаются, `admin-token` и `alerts.json` сохраняются.
Это штатный способ доустановить то, что не получилось с первого раза.
